API guide¶

The driver's API by task, with code that compiles: start, draw, scroll, follow the button, handle errors and shut down.

All of them, with the driver API for each: Datasheet map.

Every call returns Result<T> (.ok(), .error, .value); an Error is [[nodiscard]], so a dropped result is a compiler warning. Coordinates are in the visible area of the module (GetGeometry()): 96 x 64 for the ISF15ACP4.

Start and power up¶

isf15acp4::Error BringUp(Panel& panel) {
  // State 1: the controller is reset, configured and cleared; the OLED supply is still off.
  const auto r = panel.EnsureInitialized();
  if (!r) {
    std::printf("ISF15ACP4 init: %s\n", isf15acp4::ToString(r.error));
    return r.error;
  }
  return panel.DisplayOn().error; // State 2: supply on, wait, panel on.
}

EnsureInitialized() leaves the panel dark with the supply off (state 1); DisplayOn() is the only call that enables the supply (DisplayDim() does too, at the dim settings). DisplayOff() returns to state 1. Reinitialize() is the power-down, start-up and the previous display state again: the repair after a brown-out you cannot see (Limitations).

Pixels¶

Color is RGB565 (MakeColor(r, g, b) builds one from 8-bit channels; kBlack, kWhite, kRed, kGreen, kBlue are provided). The driver encodes it for the colour depth in the configuration: two bytes in 65k mode, one in 256 and three in 65k format 2.

Call Does
Clear(color) Fills the visible area
SetPixel(x, y, color) One pixel
FillWindow(x, y, w, h, color) A rectangle by streaming data (no engine)
WriteWindow(x, y, w, h, pixels) A window of w * h colours, row by row
WriteWindowRaw(x, y, w, h, bytes) A window of bytes you encoded yourself
Present(frame) A whole frame of width * height colours 
isf15acp4::Error ShowIcon(Panel& panel) {
  // A 4 x 2 window of colours, written row by row whatever the RAM increment mode.
  const std::array<isf15acp4::Color, 8> icon{
      isf15acp4::kRed,  isf15acp4::kGreen, isf15acp4::kBlue,  isf15acp4::kWhite,
      isf15acp4::kBlue, isf15acp4::kWhite, isf15acp4::kBlack, isf15acp4::kRed};
  return panel.WriteWindow(10, 20, 4, 2, icon).error; // InvalidArgument sends nothing
}

With Remap::vertical_increment the controller fills columns first; the driver reorders the pixels, so the picture is the same. A window outside the visible area, or a span of the wrong length, is InvalidArgument and sends nothing.

The drawing engine¶

The controller draws lines and rectangles, copies, dims and clears a window by itself, from a few bytes of command. The driver waits Config::engine_settle_us after each, because the datasheet gives no busy time (Ambiguities).

isf15acp4::Error Frame(Panel& panel) {
  // The controller draws these itself: one short command each, then a wait for the engine.
  if (auto r = panel.FillRectangle(2, 2, 60, 20, isf15acp4::kWhite, isf15acp4::kBlue); !r) {
    return r.error;
  }
  return panel.DrawLine(0, 63, 95, 0, isf15acp4::kGreen).error;
}

DrawLine, DrawRectangle, FillRectangle, CopyWindow, DimWindow and ClearWindow check that corners are ordered and inside the visible area. The engine's fill option is switched on only for FillRectangle and off again after it.

Scroll¶

isf15acp4::Error Ticker(Panel& panel) {
  isf15acp4::ScrollSetup s{};
  s.columns = 1;    // one column per step to the left
  s.start_row = 40; // the bottom 24 rows scroll
  s.rows = 24;
  s.interval = isf15acp4::ScrollInterval::Frames10;
  if (auto r = panel.SetupScroll(s); !r) {
    return r.error; // InvalidArgument: nothing sent
  }
  return panel.ActivateScroll()
      .error; // RAM writes are refused (ScrollActive) until it is deactivated
}

While scrolling, RAM and engine calls, SetupScroll() and ApplyConfig() return ScrollActive (a raw 2Fh or 2Eh through TraceCommand() is tracked too). DeactivateScroll() stops it; the RAM content must then be rewritten (RamNeedsRewrite() is true until a full-area write). ScrollSetup needs a multiplex ratio of 64 for the vertical offset.

Follow the button¶

Poll() reads the switch through the port, debounces it and returns one ButtonUpdate; call it at least twice per debounce time (every 5 ms is comfortable). The first sample after the start, Reset(), SetButtonConfig(), or an ApplyConfig() or Reinitialize() that changes the switch settings sets the level without an event (one that leaves them alone keeps a press in progress): a switch already held at that moment gives a LongPress (and was_long on the release) with no Pressed before it, and no Repeat. repeat_delay_ms of 0 repeats at the first held poll, and a repeat delay shorter than long_press_ms delivers Repeat before LongPress. If the wake DisplayOn() fails, Poll() returns its error and the Pressed event is lost, although GetButtonPressCount() has counted it.

ButtonEvent When Fields
Pressed the level was closed for debounce_ms timestamp_ms: when it first changed
Released open for debounce_ms held_ms, was_long
LongPress held for long_press_ms, once per press held_ms
Repeat every repeat_interval_ms after repeat_delay_ms, if non-zero held_ms 
void FollowButton(Panel& panel) {
  // Call this at least twice per debounce time (20 ms by default).
  const auto u = panel.Poll();
  if (!u) {
    std::printf("poll: %s\n", isf15acp4::ToString(u.error));
    return;
  }
  switch (u.value.event) {
  case isf15acp4::ButtonEvent::Pressed:
    std::printf("pressed at %u ms (press %u)\n", static_cast<unsigned>(u.value.timestamp_ms),
                static_cast<unsigned>(panel.GetButtonPressCount()));
    break;
  case isf15acp4::ButtonEvent::LongPress:
    std::printf("long press\n");
    break;
  case isf15acp4::ButtonEvent::Released:
    std::printf("released after %u ms\n", static_cast<unsigned>(u.value.held_ms));
    break;
  default:
    break;
  }
}

With Config::idle_dim_ms and idle_sleep_ms set, Poll() dims and then turns the display off after that long without a press, and a press wakes it (woke_display is true: treat that press as a wake, not as a command). Only a display that the idle timers lowered is woken: one that you dimmed or switched off yourself stays as it is. The idle timers run inside Poll(), which needs the switch: on the display-only Isc01p, Poll() returns Unsupported and the idle timers never act; dim or switch off from your own timer there. NotifyActivity() restarts the idle timers. ButtonDebouncer can also be used alone, with your own samples.

Configuration at run time¶

Setters take effect at once and are checked first: SetContrast, SetMasterCurrent, SetPrechargeSpeed, SetRemap, SetStartLine, SetDisplayOffset, SetDisplayMode (normal, all on, all off, inverse), SetMultiplexRatio, SetDimSettings, SetPowerSave, SetPhasePeriods, SetClock, SetGrayScaleTable, UseLinearGrayScale, SetPrechargeLevel, SetVcomh, Nop. ApplyConfig() sends a whole Config. SetCommandLock(true) locks the controller against commands; every call but the power-down then returns Locked. SetDimSettings refuses a dim contrast above the start-up contrast of its colour, and SetContrast a contrast below the dim contrast (NKK notes, ACh). Call SetupScroll with the display off, as the NKK notes require for 27h; NKK Note 1 warns that changed set-up values may damage the module.

What a restart (Reinitialize(), or ApplyConfig(GetConfig())) keeps: every setter stores its value in GetConfig() and the restart sends it again, with three exceptions. SetMultiplexRatio is not stored (the module's ratio comes back), SetGrayScaleTable is not stored (the start-up gray scale comes back: B9h when linear_gray_scale is set), and SetPrechargeSpeed sets send_precharge_speeds, so its values are sent again even on the two smaller modules. A setter whose transfer failed leaves GetConfig() as it was.

TraceCommand(opcode, parameters) sends one raw command for bring-up; it checks the opcode and parameter count against the command table and marks the shadow in doubt. It bypasses the guards of the typed calls: a raw A8h or 27h can break the rule that a vertical scroll needs 64 MUX, and the driver will not notice. A raw 2Fh or 2Eh keeps IsScrolling() in step, FDh takes only 12h or 16h and ADh only 8Eh.

Handle errors¶

const char* Describe(isf15acp4::Error e) {
  switch (e) {
  case isf15acp4::Error::Bus:
    return "a transfer or pin write failed: the chip state is unknown, call Reinitialize()";
  case isf15acp4::Error::NotInitialized:
    return "call EnsureInitialized() first";
  case isf15acp4::Error::ScrollActive:
    return "deactivate the scroll before writing RAM";
  case isf15acp4::Error::Locked:
    return "SetCommandLock(false) first";
  default:
    return isf15acp4::ToString(e);
  }
}
Error What to do
InvalidArgument Fix the argument; nothing was sent
NotInitialized Call EnsureInitialized()
Bus The state of the controller is unknown: Reinitialize(), then redraw
Unsupported Add the optional hook, or the module has no switch
ScrollActive DeactivateScroll() first, then rewrite RAM
Locked SetCommandLock(false)
SupplyOff DisplayOn() first

Shut down¶

void PowerDown(Panel& panel) {
  // Runs every step whatever the state, and drives the supply off even when a transfer fails.
  if (auto r = panel.Deinitialize(); !r) {
    std::printf("ISF15ACP4 power-down: %s\n", isf15acp4::ToString(r.error));
  }
}

Deinitialize() is never refused. Cut VDD only after it returns.
