Detailed Description

template<SpiPort Port>
class isf15acp4::ISF15ACP4< Port >

Driver for one ISF15ACP4 on a platform port.

Lifecycle (NKK sheet E7, states 0 to 2): construct with the configuration (no I/O); EnsureInitialized() resets the controller, sends the configuration and clears GDDRAM with the OLED supply still off (state 1); DisplayOn() enables the supply and turns the panel on (state 2); DisplayOff() turns it off and the supply off (state 1); Deinitialize() is the power-down and always runs. The supply is never enabled before the controller has been configured. Every call that touches the chip returns Error::NotInitialized until EnsureInitialized() has succeeded.

Optional port hooks, found at compile time:

Hook Used for Without it
bool ReadSwitch(bool& high) noexcept Poll(), ReadSwitchRaw(): the switch pin Those calls return Unsupported
uint32_t NowMs() noexcept Timestamps of the debouncer, the idle timers Poll() and NotifyActivity() return Unsupported
void Log(LogLevel, const char* message) noexcept One line per lifecycle event or failure Nothing is logged

A hook declared with the wrong signature is a compile error. Required: EnsureInitialized, Write, GpioSet, DelayUs.

◆ Deinitialize()

template<SpiPort Port>
Result< void > isf15acp4::ISF15ACP4< Port >::Deinitialize ( )
noexcept

The power-down: command unlock, display off, supply off, wait vcc_off_ms. Never refused.

It runs every step whatever the state (also on a driver that never started, also with the controller locked or scrolling) and whatever fails: the supply enable is driven off even when the display-off transfer failed. The driver is uninitialised afterwards. When it returns, the logic supply may be cut (SSD1331 section 7.9, tOFF).

Returns
Ok, or the first Bus of the steps.

◆ EnsureInitialized()

template<SpiPort Port>
Result< void > isf15acp4::ISF15ACP4< Port >::EnsureInitialized ( )
noexcept

Power up to state 1: the controller is reset, configured and cleared, the supply is off.

Drives the VCC enable off, pulses RES# for kResetPulseMinUs, sends display off and every configuration command, clears GDDRAM (Config::clear_ram), and returns. Blocks for the SPI traffic (about 12 kB with the clear) and a few microseconds of waits. After it succeeds, later calls return Ok at once with no I/O. After it fails the driver stays uninitialised, the supply is off, and the next call starts again.

Returns
Ok, InvalidArgument (the stored configuration fails Validate(); no I/O) or Bus.

◆ Poll()

template<SpiPort Port>
Result< ButtonUpdate > isf15acp4::ISF15ACP4< Port >::Poll ( )
noexcept

Sample the switch, debounce it and apply the idle timers.

Reads the pin, passes the level and the time to the debouncer and returns its event. When the display was lowered by the idle timers (dimmed or put to sleep by Poll() itself), a Pressed event wakes it (DisplayOn(), woke_display); a display that the application dimmed or switched off is not woken, and neither is a locked controller (the event is delivered and the display stays as the lock left it). If that DisplayOn() fails the call returns its error, the event is not delivered, and GetButtonPressCount() has already counted the press. When idle_dim_ms or idle_sleep_ms has passed since the last event, DisplayDim() or DisplayOff() runs. Call it at least twice per debounce time.

Returns
The update, or Unsupported (no ReadSwitch() or NowMs() hook), Bus (the switch read failed, or a transfer of the wake or the idle policy), or the errors of the display change.

◆ TraceCommand()

template<SpiPort Port>
Result< void > isf15acp4::ISF15ACP4< Port >::TraceCommand ( uint8_t  opcode,
std::span< const uint8_t >  parameters 
)
noexcept

Send one command once: one transfer, no retry, no decoding of its effect (handbook KB-CPP-129).

For bring-up. The opcode and parameter count must match Table 10. The driver cannot track what a raw command changed: IsShadowInDoubt() is true afterwards. AFh and ACh need the supply on. The checks of the typed calls do not apply: A8h and 27h can break the rule that a vertical scroll needs 64 MUX, a raw AEh, AFh or ACh does not change GetOutput(), and a raw B8h is not checked for rising widths. FDh takes only 12h (unlock) or 16h (lock), so that IsLocked() follows it; ADh takes only 8Eh (A[0] must be 0); a raw 2Fh or 2Eh updates IsScrolling().

Parameters
opcodeA command of Table 10.
parametersExactly its parameter bytes.
Returns
Ok, NotInitialized, InvalidArgument (nothing sent), SupplyOff, Locked or Bus.
