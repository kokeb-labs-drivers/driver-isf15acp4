Detailed Description

The write-only SPI port of the ISF15ACP4 driver: the CRTP base, its pin enums, the SpiPort concept and the bus requirements.

The driver never calls an SDK. It calls hooks on a class you derive from isf15acp4::SpiInterface<Self>:

Hook Contract
bool EnsureInitialized() noexcept Bring the SPI bus and every pin up at its idle level on the first call (VCC enable off, RES# high, CS# high); true at once afterwards
bool Write(DataKind kind, const uint8_t* data, std::size_t len) noexcept One write-only transfer of len >= 1 bytes: set D/C# for kind (Command low, Data high), CS# low, clock every byte out, CS# high
bool GpioSet(CtrlPin pin, GpioSignal signal) noexcept Drive RES# or the VCC enable; false when the pin could not be driven
void DelayUs(uint32_t us) noexcept Wait at least us microseconds

Optional hooks, described in isf15acp4.hpp: bool ReadSwitch(bool& high) noexcept (the switch pin's physical level), uint32_t NowMs() noexcept (a free-running millisecond counter) and void Log(LogLevel, const char*) noexcept.

The bus is write only: serial mode has no read (SSD1331 section 8.1) and the module has no MISO pin (NKK sheet E6). Write() returning true means the bytes were clocked out, never that the controller received them. What the controller needs from the bus is below as constexpr values (kSpiMode to kContinuousWord, SSD1331 section 7.1.3 and Table 21, NKK sheet E7); a port checks its settings against them with static_assert.

Pins and their idle levels (handbook KB-HW-018): before it enables an output the port drives it to its idle level, and before the first transfer. The VCC enable idles OFF (GpioSignal::INACTIVE: the 15 V OLED supply is off): this is the safety pin, and the driver also drives it off before it resets the controller. RES# idles high (INACTIVE: not in reset). CS# idles high. D/C# is set by Write() for every transfer. SCK idles low in mode 0.
